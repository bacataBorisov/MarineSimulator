# M3.4.2 — Experimental instrument runtime

Status: **a prepared experiment publishes measurements.** `ExperimentScenarioRunner.prepare` creates one `ExperimentInstrumentRuntime` from the scenario seed. Each new simulation timestamp advances that same model once. Sentences read the stored sample. A normal session has no runtime, and its NMEA is unchanged. There is no new control in the UI or in `UserDefaults`. The instrument inventory is `.agent/architecture/marine-instruments.md`.

## Sampling

The sample uses the simulation timestamp, the physical true wind, the physical true heading, speed through water, and the variation and deviation already computed for that tick. It does not call `Date()` and it does not draw again when a sentence is built. The same timestamp reuses the stored sample. `prepare` replaces the model, so a restarted experiment begins at the first draw. Default errors are zero. Negative apparent-wind or log speeds are omitted from publication.

## Availability

| Switch | Effect on the publication |
|---|---|
| Anemometer off | No apparent wind and no calculated true wind. Physical wind still updates. |
| Speed log off | No measured water speed and no calculated true wind. Apparent wind can remain. The boat still moves. |
| Gyro off | No HDT. True wind direction may use the corrected compass. |
| Compass off | No HDG. True wind direction uses the gyro measurement. |

Disabling a heading instrument does not clear `VesselTruth.trueHeading`. The ideal apparent wind still uses that physical bow.

## Heading used for true wind direction

1. The true-heading instrument, when it has a finite reading.
2. Otherwise the compass card plus its deviation and variation, each once: `normalizeAngle(compass + deviation + variation)`.
3. Otherwise calculated true wind direction is nil.

Course over ground is not a substitute. Physical true heading is not a substitute. With the gyro on, a compass error does not change true wind direction. With the gyro off, a compass error does.

## Sentences in an experiment

| Sentence | Experimental fields |
|---|---|
| MWV relative | Measured apparent wind angle and speed |
| MWV true | Calculated true wind angle and speed |
| MWD, VPW | Calculated true wind. MWD is omitted when the direction is nil |
| HDT | Measured true heading only. No magnetic fallback |
| HDG | Compass card, with deviation and variation in their own fields |
| VHW | Resolved measured heading and measured water speed |
| VBW | Water speed from the measured log. Ground speed stays the GNSS value |

ROT remains the change in steered true heading. Wire faults still run after the sentence exists. The hidden polar is not written into the publication.

## Conventions

True wind direction is the direction the wind comes from, degrees clockwise from true north, in `[0, 360)`.

True wind speed is the wind speed relative to the water, in knots. It is not a ground wind. The measurement model does not read speed over ground or course over ground, and the current vector in the simulator is still zero.

True heading is degrees clockwise from true north. Instrument true wind angle is

`TWA = normalizeAngle(trueWindDirection − trueHeading)`

in `[0, 360)`. Zero is wind from dead ahead. Angles through 180° are wind from starboard. Angles from 180° to 360° are wind from port.

The polar lookup uses a different number, the unsigned fold

`abs(calculateShortestRotation(from: trueHeading, to: trueWindDirection))`

in `[0, 180]`. That fold discards the tack. The measurement keeps it.

Apparent wind uses the same boat frame as `computeAWS` and `computeAWA` in `NMEA/NMEASimulator+WindCalculations.swift`. The wind vector points toward the direction the wind comes from. The vessel's velocity through the water lies along the bow.

## Forward equation

With `TWA` in radians and speeds in knots:

```text
apparent_x = TWS * cos(TWA) + STW
apparent_y = TWS * sin(TWA)
AWS = hypot(apparent_x, apparent_y)
AWA = normalizeAngle(atan2(apparent_y, apparent_x))
```

When speed through water is exactly zero, apparent wind is the true wind unchanged, including a zero true wind whose angle stays defined. That is the sentence builder's special case, and it avoids `atan2(0, 0)`.

## Inverse equation

The calculated true wind uses the measured apparent wind and the measured speed through water. It does not read the physical true wind.

```text
true_x = AWS * cos(AWA) − STW
true_y = AWS * sin(AWA)
TWS = hypot(true_x, true_y)
TWA = normalizeAngle(atan2(true_y, true_x))
TWD = normalizeAngle(heading + TWA)
```

A zero speed through water returns `TWS = AWS` and `TWA = AWA`. A recovered vector of length zero has speed 0 and no angle. That is a vessel moving through still air. The physical true-wind direction is not observable in that case.

`heading` in that last line is the measured true heading, not the physical bow:

```text
measuredHeading = normalizeAngle(physicalHeading + bias + noise)
TWD = normalizeAngle(measuredHeading + TWA)
```

The forward equation still uses the physical heading. A true-heading error therefore changes calculated true wind direction and leaves apparent wind, calculated true wind speed, and calculated true wind angle unchanged. A missing or non-finite physical heading produces no measured heading. Calculated true wind direction stays nil and is not filled with the physical heading or the compass. Zero degrees is a real heading. `InstrumentAvailability.trueHeadingInstrument = false` also leaves that direction nil while apparent wind can still be formed from the physical bow.

## Magnetic compass

East-positive, and each reference is applied once. This is the same sign as `trueHeading = normalizeAngle(magnetic + variation)` in `SimulationEngine`.

```text
magnetic = normalizeAngle(trueHeading − variation)
compass = normalizeAngle(magnetic − deviation)
measuredCompass = normalizeAngle(compass + bias + noise)
```

The compass card is the experimental HDG heading. Deviation and variation stay in their own fields and are not added again. A normal session still puts the magnetic course in HDG. Course over ground is not a substitute for true heading. A missing variation or deviation leaves the compass nil. Zero is a real reference.

## Sensor error

Primary channels are apparent wind speed, apparent wind angle, speed through water, the true-heading instrument, and the magnetic compass. Heading is degrees clockwise from true north. The true-heading instrument is not the compass and it is not course over ground.

```text
measured = ideal + bias + noise
noise ~ Uniform[-amplitude, +amplitude)
```

The positive end is not reached, because the unit draw is in `[0, 1)`. Apparent wind angle is wrapped with `normalizeAngle` after the error is added. Bias and amplitude default to zero. A non-finite bias or amplitude is treated as zero. Readings are not clamped.

A negative apparent wind speed or a negative speed through water is kept as the primary reading and is rejected by the inverse. The derived true wind is then nil. Missing or non-finite physical wind, heading, or a negative physical water speed produces no ideal apparent wind. A missing physical heading also leaves speed through water measurable. It does not leave apparent wind, because the bow defines that boat frame. Zero remains a real reading. Switching the true-heading instrument off leaves apparent wind, calculated true wind speed, and calculated true wind angle in place. Calculated true wind direction then uses the corrected compass when that reading exists, and is nil when it does not. Switching the compass off leaves the true-heading instrument in place. A negative published speed is omitted from NMEA. The stored sample may still hold the negative value.

## Random streams

`ExperimentSensorModel(seed:)` builds five `ExperimentRandomGenerator` streams. Channels 1–3 remain apparent wind speed, apparent wind angle, and speed through water. Channel 4 remains the true-heading instrument. Channel 5 is the magnetic compass. The channel seed is `experimentSeed xor (0x9E3779B97F4A7C15 * channelNumber)`. Each call advances every stream once, even when the ideal value is missing or the instrument is off.

The same seed repeats the sequence. A new model starts at the first draw. Changing one channel's bias or amplitude does not change the other channels' draws. These generators are not the physical wind and heading generator.

## Assumptions and limits

The model assumes no heel and no vertical wind. It assumes the physical true wind is already water-relative, which matches a simulator whose current is zero. It does not delay, drop, or quantize a sample. A prepared experiment calls it from `SimulationEngine` after truth is stored. The call does not change `EnvironmentTruth`, `VesselTruth`, either polar, or the vessel track. A normal tick does not call it.

The true-heading channel observes physical true heading. It is not a gyrocompass, a GNSS heading sensor, or an AHRS. Those dynamics are absent, and no accuracy number is invented. The magnetic compass is a separate channel. Variation and deviation are supplied references, not random noise, and the geographic formula is not replaced. The uniform law is not a transducer specification. **Literature reference required** before a thesis treats it as one. The vector definition is the same one the sentence builder uses. **Unverified** against a masthead instrument, a compass card, or a heading sensor.

## Later, not this task

These findings stay open. Do not treat this note as an implementation of them.

1. A normal HDG still publishes the magnetic course beside deviation. Only a prepared experiment publishes the compass card.
2. The chart heading resolver and the normal NMEA wind resolver do not use the same heading. The experiment publication uses the gyro, then the corrected compass.
3. A normal gyro field still copies physical true heading. Experimental HDT uses the measured true heading.
4. A physical heel model needs a cited sign, axis, and sensor orientation. No heel equation is chosen yet.
5. A heel or attitude sensor is a measurement, separate from physical heel.
6. Heel compensation of the wind belongs with that sensor model. It is not another independent noise term.
