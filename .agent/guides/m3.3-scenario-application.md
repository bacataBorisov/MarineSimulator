# M3.3 — In-memory scenario application

Status: **M3.3.1 truth speed is independent of the reference profile.** Do not start M3.4.

## Purpose

`ExperimentScenarioRunner.prepare(_:from:)` copies a clean `ExperimentRuntime` and installs one sanitized scenario. It does not write `SimulatorSettings`, `SimulationInputMirror`, `UserDefaults`, or any UI state.

## What the copy receives

- `ExperimentRandomGenerator` seeded from the scenario.
- `SimulationConfig.boatProfile` and `VesselObservation.referenceProfile` set to the reference polar.
- `SimulationState.hiddenPolarOverride` set to the hidden polar.
- Steady true wind written to the wind setpoints, with wind offset forced to zero, and to `EnvironmentTruth`.
- Manual weather and `BoatSpeedMode.estimated`.

The existing `SimulationEngine.tickSimulation` then advances that runtime. There is no second physics path.

## What stays inactive

`ExperimentCurrentProgram` remains on the scenario record. The runner does not copy set or drift into GPS, SOG, COG, or STW.

A normal tick that never calls the runner keeps a nil hidden override and a nil experiment generator.

## Isolation

The hidden profile is stored only on `hiddenPolarOverride`. The observation and the NMEA snapshot have no field for it. Sentence builders still read the snapshot. A late tick continues to publish `config.boatProfile` as the observation's reference profile.

Estimated speed reads `hiddenPolarOverride` when it is set, and `SimulationConfig.boatProfile` when it is not. The target is that table's speed multiplied by the speed-offset penalty, performance factors, and maneuver retention. It is not a reference speed scaled by a hidden-to-reference ratio. First-order response still filters that target from the current STW.

The reference profile is copied to `SimulationConfig.boatProfile` and `VesselObservation.referenceProfile`. Those fields do not enter the speed lookup. The same hidden profile, wind, seed, and initial state therefore keep the same latitude, longitude, heading, STW, SOG, and COG when only the reference changes.

A hidden profile with no speed table holds the previous STW. That hold is not replaced by the previous SOG. A normal session leaves the override nil, so Extasy still uses its own table and Nimana still holds STW. If that normal Nimana STW is missing, movement can still use SOG. An explicit hidden Nimana override does not.

The published boat speed is the generated truth speed. The hidden profile's name stays off the observation, the snapshot, and NMEA sentences.

## Verification

`ExperimentScenarioRunnerTests` covers identical seeds, steady wind, reference/hidden separation, an inert current, an unprepared tick, and a second scenario prepared after an earlier run.
