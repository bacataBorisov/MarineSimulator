M2.5.1: a tack and a gybe both finish at `normalize(2 × capturedTWD − HDG)`, the other tack at the absolute true wind angle captured at the start. Tack sweeps through captured TWD. Gybe sweeps through captured TWD + 180°, including the long way. Port is wind on the port side (`normalize(TWD − HDG)` above 180°). Starboard is wind on the starboard side (that angle in `(0°, 180°)`). A command for the current tack, head-to-wind, or dead downwind does nothing. The captured target does not follow a later wind shift.

## What exists

One dashboard button, **Tack**, calls `beginTackManeuver`. It picks the farther close-hauled heading. `beginGybeManeuver` mirrors the current true-wind angle and has no control. The heading curve is smoothstep on a 60 Hz `Timer` (`.common`). Speed retention and recovery stay in `SimulationEngine` and are not shown.

Port close-hauled is `normalize(TWD + optimal)`. Starboard close-hauled is `normalize(TWD − optimal)`. Optimal comes from the selected boat profile. Duration is `(6 + turnSize / 18 * 10)` clamped to 6…20 s.

## Jitter

The smoothstep curve does not reverse. The published heading does.

During a maneuver, `applySimulatedTrueHeading` writes `gyroHeading` and `heading` about 60 times a second. Those are struct properties, so each write runs `didSet` → `syncInputMirror` and an immediate settings encode. The transmit tick then copies that mirror into the runtime at 20 Hz. About 10 times a second, `applyRuntimeToMain` writes the older runtime heading back onto the dashboard, which runs `didSet` again and pulls the mirror backward. The next animation frame jumps forward along the curve.

That is a real heading reversal of a fraction of a degree to a few degrees, at the 10 Hz publish beat. It gets larger as the turn rate rises. The compass applies every tack notification with easing off, so it shows the reversal. The map uses the newest transmitted HDT, which is sampled on the simulation queue, so the icon and the dial are not the same number. The 1 Hz heading redraw is already suppressed while `tackAnimationInProgress` is set. Wrap math is the shortest arc and is not the oscillation.

The 60 Hz timer on `.common` is also the clock project memory says not to use for UI work, because it can run during MapKit layout. Removing it is deleting the second writer, not slowing the turn down.

## Commands

Four commands, one destination each. `A` is the profile’s optimal upwind angle.

| Command | Target true heading | Arc must contain |
|---|---|---|
| Tack to port | `normalize(TWD + A)` | true wind |
| Tack to starboard | `normalize(TWD − A)` | true wind |
| Gybe to port | `normalize(TWD + 180 − A)` | true wind + 180° |
| Gybe to starboard | `normalize(TWD + 180 + A)` | true wind + 180° |

The arc is the one that contains that axis, including the long way. Shortest-arc animation is not used when it would tack across a gybe or the reverse. A turn of 0.5° or less, or a missing anemometer or heading source, does nothing.

Behavior:

- The same command while that maneuver is in progress: ignore.
- A different command: start it from the current true heading. Speed through water is not reset. The old recovery is replaced by the new maneuver.
- Heading already on that target: ignore.
- True wind changes while the maneuver runs: keep the captured start, target, and wind. Do not retarget. The polar may still use the new wind for speed.
- Heading slider or nudge during a maneuver: stop the animator and enter the existing recovery. The user’s heading stands. Sliders are disabled while the maneuver owns heading, so this is an explicit cancel rather than a second writer.

`ActiveManeuver.duration` and the animation duration are the same number. Retention and recovery stay in `SimulationEngine`. Instant recovery still ends on the following tick. First-order recovery still ends after `max(3τ, 1)` seconds.

## Controls

Boat tab only. Replace the full-width Tack button with four compact buttons in a 2×2 grid. The active one reads “In progress”. The others stay enabled. Add Cancel, enabled only while a maneuver or recovery is active.

Disclosure on the same tab, persisted with the other simulator settings:

- Tack duration and gybe duration, in seconds. Empty means today’s turn-size formula.
- Tack speed retention and gybe speed retention, the existing factors.
- Recovery and heading transition are text, not extra state. Transition stays smoothstep. Recovery text shows the rule above.

Heading editors now live on Dashboard → Boat and disable while a maneuver owns heading. The Heading segment is a readout.

Known layout debt, not in this change: unused `LeadingSidePanel`, duplicate preset and weather controls, GNSS/DSC toggles that do nothing, five segments in a 320 pt rail, window minimum 960×640 with both docks leaving about 328 pt of map.

## Tests

Clock-driven, no sleeps.

- Each command reaches the formula target, and the swept arc contains wind for a tack and downwind for a gybe, including a start near 0°.
- A short arc that would cross the wrong axis is not chosen.
- The same command twice does not restart. A different command restarts from the current heading and does not jump speed through water.
- An on-target command leaves heading unchanged.
- Wind stepped during the maneuver does not move the stored target.
- A setpoint write cancels into recovery and leaves the new heading in place.
- Samples of dashboard gyro, runtime true heading, and HDT through one maneuver are monotonic along the commanded arc. No sample reverses by more than a tenth of a degree.
- Manual and From Wind speeds are unchanged when no maneuver is running.
