# M2.6.4 — sail inventory and active sails

Status: **implemented.** Do not start M2.6.5. Polar library, certificate management, and session export stay out.

## Ownership

Each vessel owns its sail inventory and its stored active selection in `vessel-profiles.json`. The inventory is equipment, not built-in identity. Saving sails does not change a built-in vessel's UUID, name, hull, rig, or Farr performance.

The hoisted set used by the simulation is still `SailConfiguration` (`mainSailID`, `headsailID`, `downwindSailID`, `mainsailReef`). Those ids are the selected sail UUID strings. `adoptHoistedSails()` copies the active vessel's stored selection into that record. A sail change does not change heading, speed, or the maneuver. The next tick copies the hoisted ids into `VesselObservation`. Areas, provenance, and hidden polars stay off that record.

## Schema

Current schema is **3**. This build reads schemas 1, 2, and 3. A valid older library is rewritten once as schema 3. Missing `inventory` stays an empty list. Missing active selection stays unselected. The fresh seed includes the certificate-listed sails below. An existing library does not gain those sails during migration.

Corrupt JSON, an unsupported schema, a non-positive sail measurement, a sail that fills the wrong slot, a missing sail UUID, and one sail in two slots still throw and leave the file unchanged.

## Fields

Identity: UUID, name, category, identification, manufacturer, model, construction year, notes, provenance (`certificateListed`, `confirmedOnboard`, `userEntered`).

Measurements, metres and square metres, all optional:

- Mainsail: luff, leech, foot, area, reef count 0...3
- Headsail: luff, leech, foot, LP, area
- Symmetric and asymmetric: SLU, SLE, SF, SHW, area
- Code sail and other: luff, leech, foot, area

Rig I/J/P/E stay on the vessel. They are not sail measurements. Zero is rejected. Blank stays unknown.

Active slots: optional mainsail, optional headsail, optional downwind sail, plus the existing reef step. Downwind accepts symmetric, asymmetric, code, and other. Unselected is valid.

## Editor

Setup → Boat Profile edits the saved selection. Dashboard → Boat edits the hoisted set for the current session. None leaves a slot empty.

## M2.6.4.1 — three sail states

- Inventory: the sails stored on that `VesselProfile`.
- Saved selection: that profile's `activeSails`. This is what a vessel switch and a restart load.
- Runtime hoist: `NMEASimulator.sailConfiguration`. It may differ during a session.

A Dashboard hoist calls `setHoistedSails`. It does not write the profile. Saving the selection calls `replaceActiveSails` and does not replace a temporary hoist. Leaving the vessel and coming back loads the saved selection again.

## Vessel switch

`selectVessel` sets the destination vessel, then `adoptHoistedSails` replaces the hoist with that vessel's saved selection, including its reef. It publishes `vesselObservation` and the running `transmitRuntime` before it returns. Heading, speed, and the maneuver stay. Empty saved slots stay empty. An unresolved vessel gets an empty hoist and `runSimulationCycle` does not publish a new cycle.

A tick that started before the switch cannot put the previous vessel's sail ids back. Publication stamps the hoist and boat profile already adopted on the simulator.

## Reef and deletion

Reef lives on both the saved selection and the runtime hoist. A switch replaces the reef. It does not keep the previous vessel's reef. Removing the mainsail sets the reef to full. A mainsail with a known reef count cannot keep a deeper reef; the hoist drops to full. A mainsail with no reef count, including every certificate-listed mainsail, does not constrain the reef step.

Deleting a hoisted sail clears that runtime slot and that saved slot. Other slots stay. A failed write leaves the inventory and the hoist unchanged. Editing a sail keeps its UUID. Duplicating a sail or a vessel creates a new UUID.

## Observation

`VesselObservation.sailConfiguration` is the runtime hoist. It does not include sail area, provenance, or the hidden polar. NMEA sentences do not carry sail ids. The observation's `referenceProfile` is the sailing-band profile (`beneteauFirst407` or `nimana`), not the vessel UUID.
